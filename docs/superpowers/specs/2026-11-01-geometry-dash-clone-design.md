# Geometry Dash 同人复刻 · 设计文档

- 日期：2026-11-01
- 状态：已获用户批准（设计三节 + git init）
- 范围：一个可玩的关卡，方块 + 飞船两种模式

---

## 1. 目标与非目标

**目标**

1. 手感对齐 Geometry Dash 2.2 的官方物理常数（不是"差不多"，是数值可追溯）。
2. 画风为原版同风格的自绘素材：分层视差背景、描边方块、白描尖刺、双色方块图标、粒子拖尾。
3. 双击 `index.html` 即可在浏览器游玩：无构建、无外部依赖、无服务器。
4. 一关约 32 秒 / 360 格，含方块段 → 飞船段 → 方块段收尾。

**交付形态**：一个目录，内含 `index.html` + 6 个 `.js`，用传统 `<script src>` 相互引用。传统脚本在 `file://` 下可正常加载（被 CORS 拦的是 ES module 和 fetch，这里两者都不用），所以"双击即玩"和"代码分文件"不冲突。音频走 WebAudio 现场合成，不加载任何音频文件。

**非目标**（明确排除，防止范围膨胀）

- 关卡编辑器、多关卡选择、成就/货币/解锁系统、在线功能。
- UFO / 波浪 / 球 / 机器人 / 蜘蛛 / Swing 等其余模式。
- 原版美术贴图、原版音乐、原版关卡排布的复制。
- 移动端触屏优化以外的输入适配（手柄不做）。

## 3. 技术选型

**采用：原生 Canvas 2D + 自研定步长物理，无构建、无依赖。**

否决的方案及理由：

- **Phaser 3**：GD 的手感来自确定性定帧积分 + 自定义缩小判定框 + 模式特定的速度上限钳制。通用 arcade 物理引擎会持续和这些需求对抗，省下的渲染时间会全部赔回去；同时引入 CDN 依赖，破坏"双击即玩"。
- **DOM / CSS transform**：60fps 下几十个物体 + 粒子拖尾 + 视差层会掉帧，而掉帧直接摧毁手感（见 §5 定步长的意义）。

附带收益：物理层不依赖任何浏览器 API，可被测试钩子单独驱动。

## 4. 物理常数（核实值）

内部单位：**格（block）= 1 单位，秒**。1 格在逻辑画布上 = 30px。定步长 **1/240 秒**（对齐 2.2 的 240Hz 子步积分）。

### 4.1 水平速度

| 速度传送门 | 格/秒 | 说明 |
|---|---|---|
| 0.5x | 8.372 | |
| 1x | **10.386** | 基准 |
| 2x | 12.914 | 实际只有 1.243 倍 |
| 3x | 15.600 | 1.502 倍 |
| 4x | 19.200 | 1.849 倍 |

> 关键事实：门上的数字是**名义标签，不是真实倍率**。社区流传的 "1x = 8.63 格/秒" 与反编译推导冲突，本项目采用 10.386（0.9 × 5.77 px/帧 × 60 ÷ 30 px/格），来源为 GD 2.2 反编译与 GDForum 实测比率交叉验证。

### 4.2 方块（cube）

| 量 | 值 | 推导 |
|---|---|---|
| 起跳初速 | 22.36 格/秒 | 11.18 px/帧 |
| 重力 | 115.0 格/秒² | 0.9582 px/帧² × 3600 ÷ 30 |
| 滞空时长 | 0.389 秒 | 2·v0/g |
| 跳跃高度 | 2.17 格 | v0²/(2g)，可越过 2 格墙，3 格不可 |
| 跳跃水平距离 | 4.04 格 @1x | v × 滞空 |
| 下落末速钳位 | 30 格/秒 | 15 px/帧 |
| 空中旋转 | 恒定 270°/秒 | 一跳约 105°，**不按滞空时长对齐** |
| 落地旋转 | 向最近 90° 整数倍插值吸附 | |

判定规则：

- 玩家主 AABB = 1×1 格（整块）。
- 与实心方块接触致死用 0.3×0.3 格缩小框。
- 尖刺致死框：原版为可编辑矩形、无公开定值 → **本项目取中心 0.55 格宽 × 0.55 格高**，列为自调参项（§13）。
- 落地容差 0.33 格（10 units）。
- **无 coyote time**。起跳严格要求 `onGround`；长按输入会缓冲，落地瞬间自动起跳。
- 死亡 → 延迟 1.0 秒 → 从 0% 重开，尝试计数 +1。

### 4.3 跳板 / 跳环

起跳速度按 `v0 = √(2·g·h)` 换算，h 为社区核实的可达高度：

| 对象 | 可达高度（格） | 设定速度（格/秒） | 相对普通跳 |
|---|---|---|---|
| 粉跳板 | 1.933 | 21.08 | 0.94 |
| 黄跳板 | 4.533 | 32.28 | 1.44 |
| 红跳板 | 6.533 | 38.78 | 1.73（超下落钳位） |
| 粉环 | 1.083 | 15.78 | 0.71 |
| 黄环 | 2.383 | 23.40 | 1.05 ≈ 普通跳 |
| 红环 | 4.533 | 32.28 | 1.44 |

跳环需玩家按下触发，跳板为接触即触发。本项目第一关使用：粉跳板、黄环、粉环。

### 4.4 飞船（ship）

| 量 | 值 |
|---|---|
| 重力 | 115.0 格/秒²（与方块同一硬编码常数） |
| 按住时上升加速度 | 46.0 格/秒²（0.383 px/帧²） |
| 松开时下坠加速度 | 55.2 格/秒²（0.460 px/帧²） |
| 速度上限 | 上 +16.0，下 −19.2 格/秒；按住时下 −12.8 |
| 水平速度 | **与方块模式完全相同**（同一 speed × multiplier） |
| 倾角 | 目标角 = 位移方向 atan2，每帧向目标插值，约 0.11 秒追上 |

> 常见错误：把飞船水平速度单独调慢。原版不变。

### 4.5 节奏

- 官方主关通关时长 82–99 秒。本项目第一关压缩到 32 秒（用户要求"先做一关"，见 §7 时长合计）。
- **"1 格 = 1 拍" 不成立**：1x 下 1 格仅 96.3ms，相当于 623 BPM。
- 真正贴节拍的是**时间**：滞空 0.389 秒 ≈ 154.3 BPM 的一拍，且滞空时长几乎不随速度变化（0.389 → 0.398）。
- 结论：**音乐定为 154 BPM**，关卡障碍按"一次跳跃 = 一拍"的时间网格排布。这是 GD 踩点感的真实来源。

## 5. 架构与模块契约

```
level.js     关卡数据。纯 JSON：坐标 + 类型 + 段落。零逻辑、零依赖
   ↓ 只读
physics.js   唯一状态持有者。定步长积分、判定、模式切换、死亡重开
   ↓ 每帧输出只读快照
render.js    读快照绘制：视差背景层 / 物体 / 图标 / 粒子
input.js     空格 / 鼠标 / 触摸 → 归一为布尔 held，喂给 physics
audio.js     WebAudio 合成 154 BPM 鼓点+贝斯，向 physics 提供时间基准
hud.js       FPS、Attempt、进度条、死亡提示
```

依赖方向严格单向，**physics.js 不得引用 render/audio/hud**。理由：物理必须能被测试钩子单独驱动到任意时刻，这是 §12 全部验证手段的前提。

每个模块对外只暴露一个命名空间（`globalThis.GD_Physics` 等），可独立阅读、独立替换。

**定步长循环**：`requestAnimationFrame` 里累计真实时间，按 1/240 秒步进消耗，剩余不足一步的余数留到下帧。渲染读最后一步的状态。掉帧时物理步数增加而非变慢——这是手感稳定的关键。

## 6. 关卡数据格式

```js
{ meta: { bpm: 154, endBlock: 360, name: "Crossbeat" },
  segments: [ { from: 0, to: 150, mode: "cube", speed: 1, theme: "blue" }, ... ],
  objects:  [ { x: 14, y: 0, t: "spike" }, { x: 38, y: 0, t: "block" },
              { x: 60, y: 2, t: "ring_pink" }, { x: 150, y: 1.5, t: "portal_ship" }, ... ] }
```

`y` 以格为单位，0 = 地面线。`t` 取值：`spike` `block` `pad_pink` `pad_yellow` `ring_pink` `ring_yellow` `portal_ship` `portal_cube` `speed_2x` `speed_1x` `finish`。

新增物体类型 = 在 physics.js 的 switch 里加一个分支 + render.js 加一个绘制函数，不改数据结构。

## 7. 第一关内容设计

| 段落 | 格区间 | 模式 | 时长 | 内容 |
|---|---|---|---|---|
| 开场 | 0–40 | cube 1x | 3.85s | 单尖刺 → 双尖刺，教会"一跳 = 4 格" |
| 推进 | 40–110 | cube 1x | 6.74s | 2–3 格高柱阵 + 粉环组合，跳板越过 3 格墙 |
| 切船 | 110–118 | 传送门 | 0.77s | 飞船门，同时切 2x |
| 飞行 | 118–250 | ship 2x | 10.22s | 上下柱阵通道，通道高度按 ±16/−19.2 速度上限反推间距 |
| 回方块 | 250–258 | 传送门 | 0.62s | 切回 cube 1x |
| 收尾 | 258–360 | cube 1x | 9.82s | 密集节奏段，最后一组三尖刺 + 终点旗 |

合计 **32.0 秒**（各段格数除以该段速度，见上表）。

飞行段间距不凭感觉定：先跑 §12 的机器人验证，再回填坐标。

## 8. 渲染与视觉规格

逻辑画布 **427×240**（1 格 = 30px，即 14.24 × 8 格），按设备 DPR 与窗口尺寸整数放大，`image-rendering: pixelated` 保持硬边。

- 地面线位于离底 **2.2 格**（从用户提供的 1920×1080 截图量得，非官方文档值）。
- 玩家锚点 x = 屏宽/2 − 60px ≈ 5.12 格，故前方可见约 9.1 格。
- 三层背景：远景大矩形（视差 0.35）、中景矩形（0.6）、地面与物体（1.0）。原版视差系数由触发器指定、无固定值，此处取社区常见观感 0.2–0.5 区间。
- 方块：深色填充 + 2px 白描边 + 顶/左 2px 亮带。
- 尖刺：底宽 = 高 = 1 格，白描边、内部近黑渐变。
- 图标：1 格见方，黑外框 + 主色（绿）主体 + 两只方眼 + 一条横嘴，双色蒙版思路（主色/副色），**自绘不描摹原版像素**。
- 拖尾：玩家副色小方块，约 0.5 秒渐隐。
- 死亡：爆成主/副色方块碎片。原版默认无闪白、无震屏，故不加。
- HUD：左上角白色等宽小字 FPS；`Attempt N` 世界坐标跟随滚动；底部居中半透明圆角进度条 + 百分比数字。

配色为自定的蓝色主题，向截图观感靠拢但不复制其色值资产。

## 9. 音频

WebAudio 现场合成，154 BPM：底鼓 + 军鼓 + 闭镲 + 一条贝斯线，四小节的循环，段落切换时移调。不加载任何音频文件，因此没有 fetch 和 CORS 问题，双击即玩不受影响。

首次用户手势后才 `resume()` AudioContext（浏览器自动播放策略）。

---

## 10. 输入

`keydown(Space)` / `pointerdown` / `touchstart` → `held = true`；对应 up 事件 → `held = false`。方块模式读 `held` 的边沿起跳 + 落地自动连跳；飞船模式读持续状态。

阻止空格滚动页面。窗口失焦时强制 `held = false`（防止回来时飞船一直上升）。

---

## 11. 错误处理

只处理真实会发生的：

1. AudioContext 未授权 → 首次手势启动，失败则静音继续，不阻塞游戏。
2. 切后台导致 dt 爆炸 → 单帧 dt 钳制 50ms（最多 12 个物理步）。
3. 窗口缩放 / DPR 变化 → 重算整数缩放比，不改逻辑分辨率。
4. `level.js` 数据缺字段 → 启动时校验并明确报错（这是外部输入边界，值得校验）。

其余不加。内部模块之间不做防御性校验。

## 12. 验证与测试

**环境事实**：本机无 Node（`node` 不在 PATH，`C:\Program Files\nodejs` 不存在，Qoder 目录内无 `node.exe`）；`node-repl` 运行时无 `require`、无 `process`、无文件系统，仅可算数。可用：Python 3.11/3.14、Chrome、Edge、browser-use 浏览器控制。

**因此测试在真实浏览器中执行**，游戏暴露 `window.__GD_TEST__`：

```js
__GD_TEST__ = {
  step(n)            // 前进 n 个物理步，返回状态
  feed(seq)          // 注入按键序列 [{at:秒, down:bool}]
  measure()          // 返回 {airtime, apexBlocks, spanBlocks}
  state()            // 返回当前 x/y/mode/speed/alive/percent
}
```

测试清单：

| 编号 | 内容 | 断言 |
|---|---|---|
| T1 | 常数回归 | 滞空 0.389s、跳高 2.17 格、@1x 跳距 4.04 格，误差 >2% 即失败 |
| T2 | 速度表 | 四种门速下 1 秒内水平位移匹配 §4.1 表格，误差 >2% |
| T3 | 通关机器人 | 关卡定稿后由我手写按键序列，作为测试数据入库（`tests/replay-crossbeat.js`）；喂入后断言 `percent === 100` 且全程 alive。这证明关卡人类可通 |
| T4 | 飞船钳制 | 持续按住 2 秒，y 速度收敛到 +16.0；松开收敛到 −19.2 |
| T5 | 死亡重开 | 撞刺后 1.0 秒内 alive=false，之后 x 归零、attempt+1 |
| T6 | 稳定性 | 随机输入 3000 步无异常、无 NaN |

**人工验证**：我自己在浏览器里连打一遍，确认手感；UI/交互类改动必须实跑，不看代码通过就算完成。

## 13. 未证实项 / 自调参项（诚实清单）

以下**没有权威来源**，是我的判断，做完可能需要调：

1. 尖刺致死框 0.55 格 —— 原版可编辑、无公开定值。
2. 地面线离底 2.2 格 —— 单张截图量测，中低置信度。
3. 视差系数 0.35 / 0.6 —— 原版由触发器逐段指定，无全局默认值。
4. 可见区 8 格高 —— 由 427×240 反推，社区另有 10 格说法，两者冲突未解。
5. 拖尾长度 0.5 秒、FPS 文字颜色 —— 未证实。
6. 关卡段落长度与间距 —— 我的设计，不是原版规律。
7. 跳板"上升中掠过不触发" —— **自调参项，偏离 §4.3 的"接触即触发"**。GD 里跳板是钉在方块底部的实体，玩家踩不到板子下面；本项目的跳板是独立的 0.35 格薄片，"从下面穿过"这种情形原版不存在，方向得自己定。本项目取"vy<=0 才给冲量"：贴地跑过会弹、从高处砸下来会弹、上升中掠过不弹。关卡里两处跳板都在地面上，实测不影响可通性。是否改成真正的"每次接触一次冲量"，留 Task 13 人工试玩定夺。
8. **传送门/速度门的触发框高度 `GATE_H = 256` 格** —— **自调参项**：原版段落末尾的门是不是通高，仓库里没有可核实的依据。本项目取"通高"（框从门底 `o.y` 往上延伸），高度按可推导的上界取值：飞船爬升被 `CAP_UP` 钳在 16 格/s，从切船门 x=111.5（玩家还贴着地面）到回方块门 x=252.5 最多 13.6 s（按最慢的 1x 算）→ 最多爬 217 格，256 盖得住（实测 1x 最坏情况爬到 215.75，余量 40.75 格）。24 格**盖不住**：实测按住不放能爬到 y≈173（2x）/ 216（1x），两扇门都够不着，玩家以飞船 2x 直接飞过收尾段通关。
9. **触发框的底边取门的 `o.y`，不是 0** —— 自定语义：悬在半空的门只在这一层高度触发，不该被贴地玩家吃到。底边改成 0 会让"这一层高度的门"变成"整根柱子都触发"。
10. **切回方块时只在"判定在地面"才清 `vy`，空中保留** —— 自定语义：切换只换操作方式，不该凭空吃掉玩家上升的动量（动量连续性）；在地面时清是"在地面 ⇒ vy==0"不变式的要求。空中保留并不消除"多飞一下"，那是方块模式本来的跳跃弧线，留 Task 13 手感校准。
11. **飞船段的天花板高度 `y = 9`（x∈[118,252] 连续铺满）** —— **自调参项**：原版的天花板是关卡设计的一部分，这里是补上去的。为什么是 9：天花板必须**低于**通道里最高的柱块（y=10）——放在 y=11 的话飞船仍能以 y=10.7 从所有柱顶飞过，等于没封。为什么止于 252：回方块门在 x=253，触发框是 x∈[253,254.4]，天花板铺到 253 会让 L3 的"门框不压障碍"变红。**效果**：飞船最高 y=8.72，按住不放会在 x≈120 撞顶死——**以前能飞到 y=46.55 从柱阵顶上飞过去，以 2x 直接飞过整个收尾段通关**。**残余事实**：天花板只在 y=9，玩家仍可以在通道里走高（各列安全带的上沿到 8.25 左右，通道本身是"上下柱阵"，高空是合法路线的一部分）；这不是漏洞，是关卡设计。
12. **通关序列是反推出来的，不是人手打出来的** —— 预研用求解器搜出来的 170 事件序列（方块段/收尾段是搜索器的结果，飞船段是反馈控制器生成的，每 12 帧决策一次）。它能通关，但**不是人类手感的最优解**，Task 13 实玩之后可能要重写。

## 14. 交付物与验收标准

**交付**：`index.html` + `level.js`/`physics.js`/`render.js`/`input.js`/`audio.js`/`hud.js`（双击 index.html 即玩）、`tests/` 下的浏览器测试脚本与回放数据、本设计文档。

代码用传统 `<script>` + `globalThis` 命名空间，**不用 ES module**——因为 ES module 在 `file://` 下会被 CORS 拦截，破坏"双击即玩"。

**验收**：

1. T1–T6 全绿。
2. 双击 `index.html` 能直接玩，无需服务器。
3. 一关能打到 100%，且死亡重开正常。
4. 截图对比：布局、描边风格、HUD 位置与原版观感一致。
5. 不含任何原版素材或音乐。
